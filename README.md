# نیکیا — فروشگاه اینترنتی پوشاک زنانه

فروشگاه فارسی و راست‌چین با Next.js، بر اساس طراحی «نیکیا» (کرم و مشکی، فونت Estedad).
شامل ویترین کامل (خانه، فروشگاه با فیلتر، صفحه‌ی محصول، سبد، پرداخت آنلاین، حساب کاربری)
و پنل مدیریت (محصول، موجودی، سفارش، تخفیف، فروش حضوری، پیام‌ها و خبرنامه).

> این پروژه روی **Vercel + Turso** اجرا می‌شود. ارسال: **یک هزینه‌ی ثابت** (با سقف ارسال رایگان
> قابل تنظیم). پرداخت: **فقط آنلاین**. بلاگ و لوک‌بوک عمداً وجود ندارد.

## استک فنی

| بخش | انتخاب |
|---|---|
| فریم‌ورک | Next.js 16 (App Router، Turbopack)، React 19، TypeScript |
| دیتابیس | Prisma + SQLite محلی؛ روی سرور: Turso (libSQL) |
| احراز هویت | Better Auth: ورود با کد پیامکی (OTP) و با ایمیل + رمز |
| استایل | Tailwind v4، shadcn/ui، فونت Estedad (میزبانی‌شده روی خود سایت) |
| سبد خرید | Zustand (ذخیره در مرورگر، بازبینی قیمت و موجودی روی سرور) |
| تصاویر | ArvanCloud Object Storage (سازگار با S3)، sharp برای تبدیل به WebP |
| تست | Vitest (منطق سفارش، موجودی، تخفیف، پرداخت) |

## ۱. راه‌اندازی محلی

```bash
npm install
cp .env.example .env          # سپس BETTER_AUTH_SECRET را پر کنید (openssl rand -base64 32)
npm run db:apply              # ساخت جدول‌ها در prisma/dev.db
npm run db:seed               # داده‌ی نمونه: ۶ دسته، ۱۲ محصول، سایزها، کد NIKIA10
npm run dev                   # http://localhost:3000
```

بدون هیچ تنظیم اضافه‌ای می‌توانید سایت را ببینید و یک سفارش آزمایشی ثبت کنید:
کد پیامکی در کنسول سرور چاپ می‌شود و پرداخت از «درگاه آزمایشی» می‌گذرد.
(این دو رفتار **فقط در حالت توسعه** فعال‌اند؛ بخش‌های ۶ و ۷ را ببینید.)

### ساخت اولین حساب ادمین

۱. در سایت ثبت‌نام کنید (`/register`). ۲. سپس:

```bash
npm run make-admin -- you@example.com        # یا شماره موبایل: 09121234567
npm run make-admin -- you@example.com --role=SUBADMIN
```

نقش `SUBADMIN` فقط به محصولات، دسته‌بندی‌ها، سایزها و فروش حضوری دسترسی دارد. بقیه‌ی بخش‌ها
(سفارش‌ها، تخفیف، کاربران، تنظیمات، پیام‌ها، خبرنامه) فقط برای `ADMIN` است.

## ۲. متغیرهای محیطی

همه در `.env.example` توضیح داده شده‌اند. مهم‌ترین‌ها:

| متغیر | توضیح |
|---|---|
| `TURSO_DATABASE_URL` / `TURSO_AUTH_TOKEN` | اگر پر باشد، همه‌جا (سایت، seed، اسکریپت‌ها) از Turso استفاده می‌شود و `DATABASE_URL` نادیده گرفته می‌شود |
| `BETTER_AUTH_SECRET` | کلید امضای نشست‌ها (اجباری در production) |
| `BETTER_AUTH_URL`، `NEXT_PUBLIC_SITE_URL` | آدرس عمومی سایت، بدون `/` انتهایی. **`NEXT_PUBLIC_SITE_URL` هنگام build خوانده می‌شود** |
| `BETTER_AUTH_TRUSTED_ORIGINS` | دامنه‌های اضافه (مثلاً `www.`) با کاما |
| `PAYMENT_GATEWAY_MERCHANT_ID` | شناسه‌ی پذیرنده‌ی درگاه (بخش ۶) |
| `SMSIR_API_KEY`، `SMSIR_VERIFY_TEMPLATE_ID` | پیامک کد ورود (بخش ۷) |
| `ARVAN_*` | آپلود عکس (بخش ۸) |
| `CRON_SECRET` | رمز فراخوانی مسیر پاک‌سازی سفارش‌ها |

## ۳. محتوای سایت

همه‌ی متن‌های ویترین در **`content/site-config.json`** هستند: منوها، متن هیرو، پیام‌های صفحه‌ی اصلی،
درباره‌ی ما، تماس، قوانین و برچسب‌ها. رنگ‌ها در `app/globals.css` (بخش `--brand-*`) هستند.

> ⚠️ **قبل از انتشار حتماً بازبینی کنید.** موارد زیر از روی طراحی و به‌صورت نمونه نوشته شده‌اند و
> ممکن است برای کسب‌وکار شما درست نباشند: تلفن، ایمیل و آدرس شوروم؛ «تأسیس ۱۳۹۸» و داستان برند؛
> «حراج تا ۵۰٪»؛ زمان‌های تحویل (تهران ۱ روز، شهرستان ۲ تا ۴ روز)؛ ۷ روز ضمانت بازگشت؛ و متن
> صفحه‌های «ارسال و بازگشت» و «حریم خصوصی». متن حقوقی را یک متخصص بررسی کند.

کد تخفیف خوش‌آمد: پیام عضویت خبرنامه کد `home.newsletter.welcomeCode` (پیش‌فرض `NIKIA10`) را نشان
می‌دهد. این کد باید در ادمین (کدهای تخفیف) وجود داشته باشد؛ seed آن را می‌سازد، اما روی سرور خودتان باید
دستی بسازید یا مقدار را از کانفیگ خالی کنید.

## ۴. دیتابیس روی Turso

`prisma db push` با Turso کار نمی‌کند، پس این پروژه اسکریپتی دارد که از روی `prisma/schema.prisma`
مستقیماً SQL می‌سازد و اجرا می‌کند (بدون نیاز به باینری Prisma).

```bash
# ۱) یک بار: turso db create nikia && turso db tokens create nikia
# ۲) ساخت جدول‌ها روی Turso (از همین سیستم خودتان):
TURSO_DATABASE_URL="libsql://nikia-....turso.io" TURSO_AUTH_TOKEN="..." npm run db:apply
```

- اجرای دوباره **بی‌خطر** است: جدول‌ها با `IF NOT EXISTS` ساخته می‌شوند و ستون‌های جدیدی که در نسخه‌های
  بعدی schema اضافه شوند با `ALTER TABLE ADD COLUMN` اضافه می‌شوند. هیچ‌چیز حذف یا بازنویسی نمی‌شود.
- تغییرهای مخرب (حذف یا تغییر نام ستون) را با `prisma migrate diff` بنویسید و SQL را بازبینی کنید.
- `npm run db:sql` فایل `prisma/schema.sql` را می‌سازد (برای مرجع یا اجرای دستی با `turso db shell`).
- **`npm run db:seed` روی Turso عمداً قفل است** (داده‌ی نمونه را پاک و بازنویسی می‌کند). برای سرور واقعی
  دسته‌ها، سایزها و محصولات را از پنل ادمین بسازید.
- بعد از اولین اجرا: ادمین ← تنظیمات، هزینه‌ی ارسال و سقف ارسال رایگان را ثبت کنید. تا آن موقع ارسال
  رایگان و بدون سقف است.

## ۵. دیپلوی روی Vercel

۱. مخزن را به Vercel وصل کنید. ۲. متغیرهای بخش ۲ را در Settings ← Environment Variables بگذارید
(`NEXT_PUBLIC_SITE_URL` را قبل از اولین build بگذارید). ۳. Deploy.

- `next build` **به دیتابیس نیاز ندارد** (صفحه‌ها موقع درخواست ساخته می‌شوند)، پس ترتیب «اول دیپلوی، بعد
  `db:apply`» مشکلی ندارد.
- `vercel.json` یک Cron روزانه (ساعت ۳ بامداد UTC) برای پاک‌سازی سفارش‌های پرداخت‌نشده تعریف می‌کند
  (پلن Hobby فقط اجرای روزانه را می‌دهد). `CRON_SECRET` را حتماً تنظیم کنید؛ Vercel آن را خودکار به عنوان
  Bearer می‌فرستد. اگر Cron اجرا نشود مشکلی پیش نمی‌آید: هر ثبت سفارش جدید هم همین پاک‌سازی را انجام می‌دهد.
- Region تابع‌ها را نزدیک دیتابیس Turso انتخاب کنید.

> ⚠️ **ریسک شناخته‌شده:** سرورهای Vercel خارج از ایران هستند. بعضی درگاه‌های پرداخت و پنل‌های پیامکی
> ایرانی درخواست‌های سرورهای خارجی را رد می‌کنند. اگر بعد از راه‌اندازی خطای اتصال به درگاه یا عدم
> ارسال پیامک دیدید، باید این دو تماس (درگاه و پیامک) از طریق یک پراکسی یا سرویس داخل ایران انجام شوند.
> قبل از باز کردن سایت برای مشتری، یک پرداخت واقعی کوچک و یک ورود با پیامک را روی سرور امتحان کنید.

## ۶. درگاه پرداخت

پیش‌فرض: **ZarinPal** (API نسخه ۴). در پنل درگاه، آدرس بازگشت را دقیقاً این بگذارید:

```
{NEXT_PUBLIC_SITE_URL}/api/payment/callback
```

سپس `PAYMENT_GATEWAY_MERCHANT_ID` را پر کنید. با `PAYMENT_GATEWAY_SANDBOX="true"` از محیط آزمایشی ZarinPal
استفاده می‌شود.

> ⚠️ اتصال ZarinPal از روی مستندات نوشته شده و با حساب واقعی امتحان نشده. تست‌های خودکار فقط منطق
> برنامه را با یک درگاه شبیه‌سازی‌شده می‌سنجند. **حتماً ابتدا در sandbox و بعد با یک پرداخت واقعی کم‌مبلغ تست کنید.**

رفتارهای مهم (همه با تست پوشش داده شده‌اند):
- نتیجه‌ی پرداخت هیچ‌وقت از آدرس بازگشت خوانده نمی‌شود؛ فقط تأیید سمت سرور (`verify`) با **مبلغ ثبت‌شده در
  دیتابیس ما** ملاک است.
- بازگشت تکراری از بانک بی‌اثر است (idempotent).
- انصراف مشتری یا رد پرداخت، سفارش را لغو و موجودی و کد تخفیف را برمی‌گرداند.
- اگر خود تأیید (verify) به‌دلیل قطعی شبکه انجام نشد، سفارش **لغو نمی‌شود** (شاید پول کسر شده باشد) و
  در حالت «در حال بررسی» می‌ماند؛ صفحه‌ی نتیجه دکمه‌ی «بررسی مجدد» دارد.
- **درگاه آزمایشی** (`/checkout/payment-simulator/...`) فقط وقتی کار می‌کند که شناسه‌ی درگاه خالی باشد *و*
  محیط توسعه باشد (یا `ALLOW_PAYMENT_SIMULATOR="true"` برای نمایش آزمایشی). در production بدون درگاه،
  پرداخت با پیام خطا متوقف می‌شود.

برای درگاه دیگر (زیبال، آیدی‌پی، …): یک فایل کنار `lib/payment/zarinpal.ts` بسازید و در
`lib/payment/index.ts` دو تابع `initiatePayment` و `verifyGatewayPayment` را به آن وصل کنید.

## ۷. پیامک کد ورود (sms.ir)

قالب «Verify» با یک متغیر `#code#` بسازید (مثلاً «کد ورود شما به نیکیا: #code# است»)، پس از تأیید،
`SMSIR_API_KEY` و `SMSIR_VERIFY_TEMPLATE_ID` را تنظیم کنید. در **production بدون این مقادیر ورود با پیامک
خطا می‌دهد** (کد هرگز در لاگ چاپ نمی‌شود). ارسال کد به ۳ بار در ۲ دقیقه برای هر IP محدود است
(محدودیت در دیتابیس ذخیره می‌شود، پس روی Vercel واقعاً کار می‌کند). ورود با ایمیل و رمز هم موجود است
و از «تنظیمات» ادمین می‌توان هر یک از دو روش را خاموش کرد.

## ۸. تصاویر (ArvanCloud)

باکت بسازید، Access/Secret Key بگیرید و `ARVAN_ENDPOINT`، `ARVAN_BUCKET`، `ARVAN_ACCESS_KEY`،
`ARVAN_SECRET_KEY` را پر کنید (اگر دامنه‌ی اختصاصی یا CDN دارید: `ARVAN_PUBLIC_URL_BASE`). سپس در ادمین
عکس محصولات (برای هر رنگ جدا)، تصویر دسته‌بندی‌ها و تصاویر هیروی صفحه‌ی اصلی (تنظیمات) را آپلود کنید.
تا آن موقع سایت با طرح‌های خطی لباس به‌جای عکس کار می‌کند. آپلود به آروان‌کلاد با حساب واقعی امتحان نشده است.

## چطور سفارش و موجودی کار می‌کند

- سبد در مرورگر است، اما در هر ورود به سبد/پرداخت با دیتابیس مقایسه می‌شود (قیمت، موجودی، ناموجود شدن).
- ثبت سفارش (`lib/orders/create-order.ts`) **همه‌چیز را از دیتابیس می‌خواند**: قیمت، نام، سایز، رنگ،
  هزینه‌ی ارسال و تخفیف. از مرورگر فقط «کدام کالا و چند عدد» پذیرفته می‌شود (۱ تا ۱۰ عدد از هر گزینه).
- موجودی با یک کاهش شرطی (`stock >= تعداد`) رزرو می‌شود؛ رزرو، مصرف کد تخفیف، آدرس و سفارش یک‌جا
  ثبت می‌شوند یا هیچ‌کدام. دو نفر هم‌زمان نمی‌توانند آخرین عدد را بردارند.
- سفارش پرداخت‌نشده تا **۶۰ دقیقه** موجودی را نگه می‌دارد و بعد خودکار لغو می‌شود. اگر مشتری خودش
  دوباره سفارش بدهد، سفارش رهاشده‌ی قبلی‌اش فوراً آزاد می‌شود.
- لغو یا استرداد از ادمین هم موجودی را برمی‌گرداند. سفارش لغو/استردادشده را نمی‌توان دوباره فعال کرد.
- ویرایش محصول در ادمین، رنگ‌ها و واریانت‌های موجود را **درجا** به‌روز می‌کند و سبدهای باز و سفارش‌های
  قبلی را خراب نمی‌کند.

## ساختار پروژه

```
app/(shop)/          ویترین: صفحه‌ی اصلی، products، cart، checkout، account، about، contact …
app/(auth)/          ورود و ثبت‌نام
app/admin/           پنل مدیریت
app/api/             auth، payment/callback، cron/expire-orders
components/          shared (کارت محصول، لوگو…)، layout، shop، account، auth، admin، ui
content/             site-config.json — متن‌های سایت
lib/orders/          ثبت سفارش و چرخه‌ی عمر سفارش (رزرو، پرداخت، لغو، انقضا)
lib/payment/         درگاه پرداخت
lib/queries/         خواندن از دیتابیس
prisma/              schema.prisma، seed، schema.sql
scripts/             schema-sql.ts، apply-schema.ts، make-admin.ts
tests/               تست‌های Vitest
```

## دستورهای مفید

```bash
npm run dev            # اجرا در حالت توسعه
npm run build          # ساخت نسخه‌ی production
npm run typecheck      # بررسی نوع‌ها
npm run lint           # ESLint
npm test               # تست‌ها (روی یک دیتابیس موقت)
npm run db:apply       # ساخت/به‌روزرسانی جدول‌ها (محلی یا Turso)
npm run db:seed        # داده‌ی نمونه (فقط دیتابیس محلی)
npm run db:studio      # Prisma Studio
npm run make-admin -- <ایمیل|موبایل>
```

## محدودیت‌ها و کارهای بعدی

- ثبت و تأیید **نظر مشتریان** رابط کاربری ندارد؛ امتیاز محصول از نظرهای تأییدشده‌ی جدول `Review`
  محاسبه می‌شود ولی راهی برای ثبت آن‌ها در سایت نیست. seed چند نظر نمونه می‌سازد.
- نماد اعتماد (اینماد، ساماندهی) در فوتر نیست؛ برای فروشگاه واقعی اضافه کنید.
- پیگیری سفارش با کد رهگیری پست ندارد (وضعیت سفارش را ادمین دستی عوض می‌کند).
- فهرست کاربران ادمین تا ۵۰۰ کاربر آخر را نشان می‌دهد و صفحه‌بندی ندارد.
- تغییرهای ادمین (دسته‌ها، صفحه‌ی اصلی، تنظیمات) تا حداکثر ۶۰ ثانیه در ویترین دیده می‌شوند (کش کوتاه).
